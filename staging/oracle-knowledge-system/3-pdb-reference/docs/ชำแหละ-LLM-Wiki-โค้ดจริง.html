03 · วิธีคิดของมัน

Prompt จริง 3 สเต็ป (Chain-of-Thought)

สเต็ป 1 — "expert research analyst"

buildAnalysisPrompt · ingest.ts:1702

สั่งห้าม output chain-of-thought · ให้วิเคราะห์เป็นหัวข้อ:

  • Key Entities — คน/องค์กร/ผลิตภัณฑ์ + มีในวิกิแล้วไหม (เช็ค index)
  • Key Concepts — ทฤษฎี/วิธี + นิยามสั้น
  • Main Arguments & Findings — ข้อสรุป + หลักฐานแข็งแค่ไหน
  • Connections to Existing Wiki — เสริม/ท้าทาย/ขยายของเดิม
  • Contradictions & Tensions — ชนกับวิกิเดิมตรงไหน
  • Recommendations — ควรสร้าง/อัปเดตหน้าไหน

ป้อน purpose.md + index.md เป็นบริบท · folder path = ใบ้การจัดหมวด

สเต็ป 2 — "wiki maintainer"

buildGenerationPrompt · ingest.ts:1753

เอาบทวิเคราะห์มาออกเป็นไฟล์ ต้องสร้าง:

  • หน้าสรุป source ที่ wiki/sources/<name>.md
  • หน้า entity / concept (ตาม schema.md = AUTHORITATIVE routing)
  • อัปเดต index.md (คงของเดิมไว้ทั้งหมด)
  • log: ## [YYYY-MM-DD] ingest | Title
  • อัปเดต overview.md (สรุปทั้งวิกิ 2–5 ย่อหน้า)

บังคับ frontmatter เข้ม: type/title/created/updated/tags/related/sources (ต้องมีชื่อไฟล์ต้นทาง = ย้อนรอยได้)

รูปแบบที่บังคับให้ LLM ตอบ (ตัวอักษรแรกของคำตอบต้องเป็น -):

// ทุกหน้าออกมาเป็นบล็อก FILE — parser อ่านด้วย regex
---FILE: wiki/entities/example.md---
---
type: entity
title: Example
created: 2026-06-13
sources: ["mysource.pdf"]   # ← ย้อนรอยแหล่งที่มา
---
# Example
เนื้อหา ... ใช้ [[wikilink]] ใน body เท่านั้น
---END FILE---

// REVIEW block (ถ้ามีจุดต้องให้คนตัดสิน)
---REVIEW: contradiction | Title---
OPTIONS: Create Page | Skip      # ← ล็อกตัวเลือก กัน AI มั่ว
SEARCH: query1 | query2 | query3 # ← เตรียม query ค้นเว็บไว้ล่วงหน้า
---END REVIEW---

REVIEW มี 4 ชนิด: contradiction · duplicate · missing-page · suggestion · ตัวเลือกล็อกแค่ "Create Page | Skip"

ของที่มัน "ยังไม่ทำ / ทำได้แค่ไหน"

  • Chat ผ่าน API ยังไม่มี — POST /chat คืน 501 ตรง ๆ (RAG ยังผูกใน WebView) → agent ภายนอก "ค้น+อ่าน" ได้ แต่ "คุย" ไม่ได้
  • คิวเป็น serial — ทีละไฟล์ต่อโปรเจกต์ (เยอะ = ช้า) แลกกับไม่ชน LLM พร้อมกัน
  • เป็นการสรุป ไม่ lossless — เก็บ raw ไว้ (immutable) แต่หน้าวิกิคือสรุป ไม่เก็บข้อความสะอาดฉบับเต็ม + log การตัดแบบ spec P.D.B
  • ค่าเริ่มต้น = คลาวด์ — LLM/web search ออกเน็ต ต้องตั้ง Ollama + ปิด Deep Research เองถึงจะ local 100%
  • single-user desktop — ไม่ใช่ multi-user/realtime/cloud sync
  • ไม่มี Decision Matrix/Twin/psychometric — เป็นวิกิทั่วไป ไม่ใช่เครื่องสกัด decision DNA

สรุปการชำแหละ: โค้ดแน่น คุณภาพ production (เทสต์ property-based/real-LLM ครบ, panic guard, repair pass). ส่วนที่ "ขโมยไอเดีย" ใส่ P.D.B ได้เลย: (1) ingest 2 สเต็ป + บังคับ output FILE/REVIEW + repair, (2) frontmatter sources[] ย้อนรอย, (3) กราฟ 4 สัญญาณ + Louvain, (4) schema ของ API/MCP (อ่านอย่างเดียว = ตัว "ถอน"), (5) เทมเพลต Business. ส่วนที่ต้องสร้างเอง: Decision Matrix, lossless เต็ม, consent/audit.
