แปลงข้อมูลดิบ 1 วันจาก PassiveINKEY → โน้ต Obsidian 1 ใบ/วัน ที่อ่านรู้เรื่อง สรุปประเด็น ลิงก์คน/โปรเจกต์ — โดยไม่ทำข้อมูลจริงหาย

📥 ดิบ 1 วัน→ 🧹 ล้าง (lossless)→ 🤖 วิเคราะห์ AI→ 📝 โน้ต Obsidian

ซับระบบที่ 2 (Curator) ของธนาคาร: ฝากดิบ → พนักงานนับ/จัด → ลงบัญชีเป็นโน้ต

ขอบเขต · เฟสนี้ทำแค่ไหน

เล็ก ครบลูป เทสได้ — ตัดส่วนซับซ้อนออกก่อน

✓ มีในเฟสนี้

  • อ่านดิบ 1 วัน → ล้างแบบ lossless
  • วิเคราะห์ด้วย AI → เขียนโน้ต Obsidian
  • สั่งผ่าน CLI ทีละวัน (node tools/digest.js <วัน>)

✕ ยังไม่มี (YAGNI — เฟสถัดไป)

  • ฐานข้อมูล · vector / semantic search
  • MCP · ถาม-ตอบ · realtime · หลายแหล่ง
  • security / audit เต็มรูปแบบ
หัวใจที่บอสสั่งย้ำ

ล้างแบบไม่ทำข้อมูลหาย (Lossless)

  • ไฟล์ดิบ PassiveINKEY อ่านอย่างเดียว ห้ามแก้/ลบ
  • เก็บ ข้อความสะอาดฉบับเต็ม เสมอ — โน้ตสรุปเป็นชั้นเสริม ไม่ใช่ตัวแทน
  • ตัดเฉพาะที่ พิสูจน์ได้ว่าซ้ำ/noise · ไม่ชัวร์ = เก็บไว้
  • ทุกอย่างที่ตัด บันทึกใน removal log ตรวจย้อนได้

กันมั่ว (no hallucination)

AI ล่ม → ข้อมูลไม่หาย

ถ้า AI ล้มเหลว ยังเขียน _full.md เสมอ + โน้ตใส่หมายเหตุ "AI ไม่สำเร็จ" · บางชั่วโมงขาดก็ทำเท่าที่มี

การเทส · TDD

ของเพียวเทสในเครื่อง · ของ AI เทสบน Mac

  • clean.js + write-obsidian.js = ฟังก์ชันเพียว → node --test ด้วย fixture จากข้อมูลจริง
  • เทสหลัก: lossless (เนื้อหาจริงไม่หาย), ตัดซ้ำได้จริง, โน้ตมี [[links]] ถูก
  • analyze.js = ยิง API → เทสบน Mac: ตรวจสคีมา JSON + entity grounding
นอกขอบเขต · เฟสถัดไป
