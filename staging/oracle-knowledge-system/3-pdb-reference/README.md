# P.D.B — Personal Data Bank (ธนาคารข้อมูลส่วนบุคคล)

> ระบบจัดการ "ฝาก–ถอน" ข้อมูลชีวิตส่วนตัวอย่างมีระเบียบและปลอดภัย
> เป็น **ชั้นถัดจาก PassiveINKEY** (ซึ่งทำหน้าที่ "นำเข้า" ข้อมูลดิบ)

**สถานะ: 🎨 ออกแบบ (design phase) — ยังไม่เริ่มเขียนโค้ด**

---

## แนวคิด (metaphor ธนาคาร)

| ส่วน | เปรียบเป็น | หน้าที่ |
|---|---|---|
| **ฝาก (deposit)** | ตู้รับฝาก | รับข้อมูลเข้า · PassiveINKEY = ผู้ฝากรายแรก (เพิ่มแหล่งอื่นทีหลัง) |
| **พนักงาน (curator)** | เทลเลอร์นับ/จัด | AI ล้าง + จัดระเบียบ + วิเคราะห์ให้มีคุณภาพ |
| **ตู้เซฟ + สมุดบัญชี** | vault + ledger | เก็บอย่างมีระเบียบ + ดัชนีว่ามีอะไรอยู่ไหน |
| **ถอน (withdraw)** | เคาน์เตอร์ | ดึงไปใช้ผ่าน MCP / AI agent / ถาม-ตอบ |
| **ยาม + กล้อง** | security + audit | คุมการเข้าถึง + บันทึกร่องรอย |

P.D.B แยกเป็นโปรเจกต์ของตัวเอง (decoupled) — PassiveINKEY เป็นแค่ "ตู้ฝาก" เครื่องหนึ่ง

---

## เป้าหมายเฟสแรก (MVP ที่ตกลงกันแล้ว)

**Daily Digest → Obsidian** : ฝากดิบ 1 วัน → ล้าง → วิเคราะห์ด้วย AI → โน้ต Obsidian 1 ใบ/วัน + ลิงก์ความสัมพันธ์

```
ดิบ 1 วัน (.md)  →  ล้าง (ตัดซ้ำ/noise)  →  วิเคราะห์ AI (สรุป+จัดกลุ่ม)  →  โน้ต Obsidian
```

ครบลูปเล็ก "ฝาก → จัด → ลงบัญชี" · ยังไม่มี DB / vector / MCP / realtime / security เต็ม (เฟสถัดไป)

---

## หลักการเหล็ก (Invariants)

1. **ล้างแบบไม่ทำข้อมูลหาย (lossless)** — ห้ามแตะไฟล์ดิบ · เก็บข้อความสะอาดฉบับเต็มไว้ด้วย · ตัดเฉพาะของซ้ำ/noise ที่พิสูจน์ได้ · มี log ว่าตัดอะไรไปเพื่อตรวจสอบ · **ไม่ชัวร์ = เก็บไว้**
2. **ข้อมูลอยู่ในเครื่อง 100%** — ไม่ขึ้น cloud/git · วางรากฐาน security/audit ไว้ตั้งแต่ต้น
3. **ห้ามมั่ว** — AI ห้ามแต่ง entity/เรื่องที่ไม่ได้ถูกพูดถึงจริง (ค่าเดียวกับ PassiveINKEY)
4. **decoupled** — รับฝากจากหลายแหล่งผ่าน interface กลางมาตรฐานเดียว
5. **ตอบ/คอมเมนต์เป็นภาษาไทย · กระชับ**

---

## โรดแมป 6 ซับระบบ

1. ช่องรับฝากกลาง (Ingestion)
2. **ตัวจัดระเบียบ AI (Curator)** ← เริ่มที่นี่ (MVP)
3. ตู้เซฟ + สมุดบัญชี (Storage + Ledger)
4. กราฟความสัมพันธ์ → Obsidian
5. เคาน์เตอร์ถอน (MCP / API)
6. ยาม + กล้อง (Security + Audit)
