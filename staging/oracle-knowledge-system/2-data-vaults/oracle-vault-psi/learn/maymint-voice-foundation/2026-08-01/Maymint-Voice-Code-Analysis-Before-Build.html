2) แผนผัง dependency จริงที่พบ

3) สิ่งที่ระบบมีอยู่แล้วและควร reuse

STT command provider

มี custom `openrouter-gemini` แล้ว รองรับ glossary จาก pinned/recent terms, แปลง non-wav ด้วย ffmpeg, ไม่จำเป็นต้องเขียน STT ใหม่ตั้งแต่ศูนย์

TTS command provider

มี `macos-say` ผ่าน `maymint_tts.sh` แล้ว ใช้ Apple/System Voice default, strip emoji, export WAV ได้ เหมาะกับฐาน voice แรก

Hermes voice engine

มี CLI push-to-talk/continuous VAD, silence detection, playback interrupt, feedback guard ใน `hermes_cli/voice.py` อยู่แล้ว

4) จุดที่ต้องระวังก่อนพัฒนา

จุดเสี่ยงหลักฐานจากโค้ดผลถ้าไม่กันแนวแก้ใน Maymint
เสียงมายย้อนเข้าหูตัวเอง`hermes_cli/voice.py` มี `_tts_playing` และ cancel recorder ก่อนพูดเกิด loop มายคุยกับเสียงตัวเองต้องมี feedback guard ใน adapter ทุกโหมด
Stop/cancel ปนกันมี `stopVoicePlayback`, `handle.cancel`, `stop_continuous(force_transcribe)` แยกกันกดหยุดแล้วไม่รู้หยุดพูด หยุดฟัง หรือยกเลิกงานออกแบบ command แยก: stop speaking / stop listening / cancel turn / emergency stop
State หลายแหล่งDesktop มี status ใน hook, playback store อีกชุด, CLI มี on_statusUI แสดงไม่ตรง backendทำ state/event contract กลางก่อน overlay
Transcript/Memory ปนกันSTT recent terms update อัตโนมัติ แต่ memory คนละชั้นจำทุกคำพูดหรือ term noise มากเกินแยก transcript log, glossary, durable memory
Provider เปลี่ยนแล้วพังHermes มี built-in/command/plugin registry แต่ Maymint custom อยู่ข้างนอกถ้าเปลี่ยน Vapi/Gemini Live อาจรื้อทั้ง flowทำ adapter interface: transcribe/speak/playback/state
Browser mic กับ CLI mic ไม่เหมือนกันDesktop ใช้ MediaRecorder/webm, CLI ใช้ sounddevice WAV 16kเทสผ่านแบบหนึ่ง แต่อีกแบบพังแยก fixtures ต่อ surface: CLI wav, browser blob, gateway audio

5) สรุปเชิงวิศวกรรม: เราควรต่อจากตรงไหน

  1. ห้ามแก้ Hermes core ก่อน — core มีระบบ voice อยู่แล้วและค่อนข้างซับซ้อน
  2. สร้าง Maymint voice adapter แยกใน `maymint-voice-foundation` ก่อน
  3. reuse STT/TTS command provider ที่มีอยู่แทนการเขียนใหม่
  4. ทำ full-turn smoke: audio/text → STT → Hermes → TTS → playback file
  5. เพิ่ม state event log แบบ JSONL ก่อน UI
  6. หลัง state นิ่งค่อยทำ push-to-talk UI/desktop overlay

6) Phase งานจริงหลังรายงานนี้

Phaseงานห้ามทำDefinition of Done
P1.1ทำ full_turn_smoke.py แยกห้ามจับ mic/realtimeใช้ wav fixture แล้วได้ wav reply + log ครบ
P1.2ทำ event log JSONLห้ามทำ UI ก่อน event stableทุก turn มี timestamps: stt_start/stt_done/brain/tts/playback
P1.3ทำ adapter interfacesห้ามผูก OpenRouter/macOS say ตรงใน UIเปลี่ยน provider ได้ด้วย config เดียว
P2Push-to-talk local harnessห้าม wake wordกดพูด/หยุด/ตอบเสียง/หยุดพูดได้
P3Safety voice commandsห้าม execute คำสั่งเสี่ยงจากเสียงทันทีคำสั่ง shell/file/browser ต้องเข้า confirmation
P4Desktop UI stateห้ามทำ overlay สวยแต่ debug ไม่ได้เห็น state, transcript, current provider, errors, stop buttons

7) คำตัดสินรอบนี้

ระบบพร้อมให้เริ่มงานจริงแบบ P1.1 ได้ แต่ต้องเริ่มจาก full-turn smoke และ event log ไม่ใช่ realtime/wake word/overlay ทันที

เหตุผล: STT/TTS/brain แยกกันผ่านแล้ว และโค้ดเดิมมี voice engine ให้ reuse แต่ state/cancel/provider boundary ยังต้องห่อให้ชัดก่อนต่อยอด Maymint
